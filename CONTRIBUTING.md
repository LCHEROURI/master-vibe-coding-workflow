# Contributing to MVCE Workflow

Thank you for helping improve the Master Vibe Coding Engineering Workflow.

MVCE is intended to remain practical, platform-neutral, evidence-driven, and usable by non-programmers as well as experienced developers.

## Good contribution areas

Useful contributions include:

- worked examples that apply the workflow to real projects;
- clearer acceptance criteria patterns;
- independent verification techniques;
- evidence-capture methods;
- deployment and rollback patterns;
- security and permission safeguards;
- adapters for specific coding agents or development platforms;
- documentation improvements;
- accessibility improvements for non-technical builders.

## Contribution principles

Please keep contributions aligned with these rules:

1. Preserve the distinction between implementation and verification.
2. Do not weaken Authority Lease boundaries.
3. Do not replace evidence with agent confidence.
4. Prefer small, reviewable changes.
5. Keep the core workflow vendor-neutral.
6. Avoid adding complexity unless it solves a documented problem.
7. Explain any new gate, artifact, or rule in plain language.

## Before opening a pull request

Please:

- describe the problem being solved;
- explain why the change belongs in the core workflow or an adapter;
- identify any new risks or assumptions;
- include examples when practical;
- keep unrelated changes out of the same pull request.

## Suggested pull request structure

### Problem

What problem does this contribution solve?

### Proposed change

What changes?

### Verification

How was the change reviewed or tested?

### Evidence

What evidence supports the change?

### Compatibility

Does this affect existing MVCE users, templates, or workflows?

## Discussion

For substantial changes to the methodology, open an issue first so the design can be discussed before implementation.
